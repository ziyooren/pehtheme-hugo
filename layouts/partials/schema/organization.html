{{- /* Organization node for JSON-LD — opt-in via params.organization. Why opt-in: this theme is shared by several sites. Without the param the rendered output stays byte-identical to the previous behaviour (publisher = a bare Organization carrying the author's name), so other sites are unaffected. Why it exists: the product sites in this network declare https://www.cnelecar.com/#organization as their parentOrganization. Search engines only consolidate those references into one entity if the identifier is also defined somewhere authoritative on the brand's own site — this is that definition. Config (hugo.yaml): params: organization: name: "CNELECAR" url: "https://www.cnelecar.com/" logo: "/favicon.png" description: "Explore the latest tech news, reviews, deals and resources." same_as: - "https://www.facebook.com/com.cnelecar" - "https://x.com/CNELECAR" Hugo lower-cases config keys, hence `same_as` rather than `sameAs`. */ -}} {{- with site.Params.organization -}} {{- /* Built as one dict literal and returned directly — deliberately no `$node = merge ...` steps. Hugo 0.153 renders with the v1.0.0 template engine, where assigning to an outer-scope variable from inside a nested `with` block loses the binding; the later `return $node` then fails with "undefined variable: $node". Newer Hugo (0.169) does not reproduce it. Cloudflare Pages pins HUGO_VERSION, so the safe form is the one that never relies on cross-block assignment. Optional fields fall back to sensible defaults rather than being merged in conditionally. */ -}} {{- return (dict "@context" "https://schema.org" "@type" "Organization" "@id" (printf "%s#organization" ((.url | default site.BaseURL) | absURL)) "name" (.name | default site.Title) "url" (.url | default site.BaseURL) "logo" ((.logo | default "favicon.png") | absURL) "description" (.description | default site.Params.description | default "") "sameAs" (.same_as | default (slice)) "founder" (dict "@type" "Person" "name" (site.Params.author.name | default site.Title)) ) -}} {{- end -}}
